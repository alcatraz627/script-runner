1. Project Overview

What is this?

The Versable Scripts project transforms raw JEGS eBay Excel exports into enhanced, normalized product data suitable for retail submission. The pipeline produces:

  • Clean product descriptions & features (LLM-generated via Claude Haiku)
  • Extracted and reviewed item attributes
  • Selected main product images
  • Generated eBay poster images (via a Next.js ImageResponse API)
  • Walmart Supplier Center loadsheets (94-column format)

Tech Stack

LayerStack
BackendNode.js 23 (CommonJS), Express 5, port 3460
FrontendSvelteKit 2 + Svelte 5 + Tailwind 4, port 5173
AI@anthropic-ai/sdk — Claude Haiku, batches of 20
Dataexceljs/xlsx, puppeteer
Pipelineengine.js config-driven, idempotent steps, in-memory job queue

Goal (top-level)

Produce 1,252 Walmart-ready product listings from raw eBay scraped data, with accurate Part Types, descriptions, attributes, clean images for each SKU, and unicode-clean, spec-compliant output Excel.

Phase 2 — Data Quality Audit & Stock Image Crisis (Mar 21–22)

Discovery: User noticed 7 SKUs all showed the same images in the dashboard. Investigation found 28 shared eBay listing URLs mapped to 162 different SKUs. The scraper had captured seller storefront gallery photos.

Multi-layered fix:

  1. Static blacklist — Known stock image URLs in BLOCKED_BASES set
  2. Extension-agnostic matching — stripExt() strips .webp/.jpg before URL comparison
  3. Frequency-based auto-detection — Any image URL appearing in 4+ SKUs → auto-classified as stock photo
  4. Two-layer filtering — Stock images stripped in both prepare-image-dataset.js (data time) and generate-combined-dashboard.js (display time)

User reaction: "What the fuck dude. Now all of them have no images." Those 7 SKUs genuinely had only stock photos — no real product images in the source data.

Attempted workarounds: jegs.com scraping → 403 Forbidden; Google Images API → no reliable programmatic access; eBay search → impractical.

Resolution: Created upsert-images.js + BACKFILL-IMAGES.md for future manual backfill. 127 items accepted as a known image gap.

Phase 3 — Normalize Audit + Post-Processing Fixes (Mar 24, Session 1)

After the pipeline ran, a comprehensive audit (audit-normalize.js) uncovered several data quality issues that slipped through.

A. Junk Attributes in Excel-Sourced Items

Problem: 68 items had eBay junk attributes (ePID, MPN, Sub Type, Notes, Type, Dimensions). Root cause: Excel-sourced Item Specifics (JSON) attrs were never routed through the review dashboard.

Fix: fix-junk-attrs.js — stripped REMOVE_KEYS from Attributes Small/Full in normalize.json and Item Specifics in raw.json. 322 attr entries removed from normalize.json; 161 from raw.json.

B. Boilerplate Descriptions (16 New SKUs)

Problem: 16 new SKUs had Claude Haiku descriptions under 500 chars. Root cause: Prompt said "Max ~500 chars" — Haiku treated this as a hard cap.

Fix: Changed prompt to "MINIMUM 500 characters" + "STRICTLY between X and Y". Created fix-boilerplate-descriptions.js with --regen flag. All 16 now 656–996 chars.

Lesson → CLAUDE.md rule: "Haiku treats 'Max ~500 chars' as a hard cap. Use MINIMUM + STRICTLY between X and Y."

C. Blocked/Stock Image URLs in Main Image Field

Problem: 92 items had the placeholder stock URL (DOcAAOSw8NplLtwK) in raw.json Main Image. Root cause: transplant-selections.js only writes explicit user picks — never clears pre-existing values.

Fix: fix-placeholder-images.js clears blocked URLs from raw.json. Also patched jegs-export-normalize.js to reject blocked URLs in the extractFirstImage fallback.

D. Part Type Field Mismatch (Silent Bug)

Problem: After any normalize re-run, Part Types reverted to eBay breadcrumbs ("eBay Motors > Parts & Accessories > ...").

Root cause: sideload-part-types.js wrote row['Part Type'] to raw.json but jegs-export-normalize.js read row['Category Hierarchy'] — two different fields.

Fix: Transform now uses row['Part Type'] || row['Category Hierarchy'] — sideloaded value takes priority.

E. Residual Fitment Attributes

Problem: 23 fitment attrs (Side, Transmission Type, Engine Type, Lug Pattern) still present after review. Root cause: Excel-sourced Item Specifics missed the dashboard fitment-cleanup step.

Fix: Stripped fitment attrs directly from normalize.json + raw.json: 46 entries removed from normalize, 23 from raw.json.

F. Zero-Attribute Items

Problem: 555-81500-6 and 555-79600 had 0 attributes — Item Specifics was empty and LLM extraction wasn't triggered.

Fix: Manually authored 4 attributes each from description content; written to both normalize.json and raw.json.

Phase 4 — Duplicate URL Discovery & Filter Transform (Mar 24, Session 2)

Discovery: 28 eBay Item URLs were mapped to 162 different SKUs. Largest group: 67 items mapped to itm/117008784933 (SSR Star Wheel 681276). The scraper had reused the same listing URL for many unrelated SKUs.

4 contaminated items had Star Wheel content on wrong products: 555-81244 (Truck Bed Lift), 555-81573 (Plasma Cutting Table), 555-50084 (Bug Catcher Scoop), 555-681437 (SSR Spike 15×10).

Fix — new transform transforms/filter-items.js: Config-driven URL exclusion list in run.config.js. Optional dedup mode. Added filter step between corrections and normalize. Pipeline now produces 440 items (down from 602).

4 contaminated items: Regenerated description, FAB, and attrs via Haiku + manual trim. All 4 now have correct product-specific content.

3.3 Description Cleaning

Boilerplate detection and regeneration: 16 new SKUs had descriptions that were either eBay-scraped HTML boilerplate or too short (< 500 chars). Regeneration used strict prompt constraints: "MINIMUM 500 characters" + "STRICTLY between 500 and 600 characters". --regen flag re-processes only failed items by saved part numbers.

Content contamination: 4 items (Truck Bed Lift, Plasma Table, Bug Catcher, SSR Spike) had Star Wheel product content from a contaminated eBay listing URL. Each required full LLM regeneration of description + FAB + attributes, plus manual trim.

3.4 Walmart-Specific Text Cleaning

Unicode normalization applied at cell write boundary:

js 9 lines 
function normalizeText(str) {
  return str
    .replace(/\u2011/g, '-')    // non-breaking hyphen
    .replace(/\u2013/g, '-')    // en dash
    .replace(/\u2014/g, ' - ')  // em dash
    .replace(/\u2019/g, "'")    _3_
    .replace(/[\u201C\u201D]/g, '"') _4_
    .replace(/\u00A0/g, ' ');   // non-breaking space
}

Why this matters: U+2011 (non-breaking hyphen) is visually identical to - but silently breaks vehicle model string matching in Walmart's ingestion (e.g., CR‑Z ≠ CR-Z). LLM output reliably produces 400–700+ typographic characters per run. Applying normalization at the single cell-write boundary means all future columns get it automatically.

8. Architecture Patterns That Emerged

PatternDescription
Config-Driven PipelineEach run has run.config.js defining input, step sequence, step-level config. Steps are idempotent. Module cache cleared before loading configs/transforms.
Sideload PatternWhen new data file has degraded quality, sideload clean data from prior run by building Map and overwriting matching rows. Transform must read sideloaded field name, not original source field.
Blacklist > Whitelist for AttrsNew attribute keys auto-include (safer for unknown data). Whitelist would silently drop unexpected keys.
Review Dashboard as HIL Gatemanual steps suspend pipeline engine, display branded dashboard, wait for user approval via DashboardBridge.signalDone(). Keeps human decisions in data flow without blocking server.
Asset-Per-Version with Sweep ToolRun sweep script against each version to find newly fillable columns. Document fill rates. Increment version only when meaningful improvement achieved.
Frequency Audit for Data QualityCounting occurrence frequencies of IDs/URLs/image hashes exposes contamination that field-level checks miss (duplicate eBay URLs, stock image reuse).
